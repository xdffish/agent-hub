# Agent Hub 产品说明

状态：访谈、兼容性限制及实施范围已由用户确认；进入实现。当前实现与验证记录见 [implementation.md](implementation.md)。
日期：2026-11-10

## 目标与用户

为同时使用多个 Coding Agent 的个人开发者，集中管理本机的 Skills、MCP 配置和插件。先做用户自己会持续使用的开源工具，再通过真实使用反馈判断商业化方向。

核心问题是资源散落、重复安装、版本不一致，以及不知道哪个 Agent 实际配置了哪些资源。现有社区讨论能支持痛点存在，尚不能证明多数用户都有该需求或愿意付费。

目标平台为 macOS、Windows 和 Linux，接入 Claude Code、Codex、Cursor、Antigravity。初版在 macOS 开发，三平台适配与验证进度见 [cross-platform.md](cross-platform.md)。具体读写能力以[官方资料兼容性调查](research/agent-compatibility.md)为准。配置可解析、资源已安装、Agent 已加载和运行可用是不同状态，不得混为一谈。

## 页面结构

### 本机概览

展示发现的四种 Agent、各自配置范围、已安装资源数、扫描异常、已检查出的更新和最近变更。未执行版本检查时显示“尚未检查”，不能显示“已是最新”。仅存在配置目录不足以判定 Agent 已安装。

入口：重新扫描、添加项目、导入资源、查看待处理差异。扫描只覆盖已知全局配置位置和用户添加的目录，不递归搜寻整台机器。

### 资源库

按 Skills、MCP、插件筛选，搜索名称与来源。详情展示类型、来源、版本或内容标识、安装位置、目标 Agent、作用域、依赖、兼容性与状态。Skills 同名不自动视为同一资源。

Skill 操作：导入、选择共享版本、按目标启用、查看差异、检查更新、固定版本、移除安装关系、删除共享资源。

MCP 操作：添加、编辑、按目标分配、按需检查连接、查看脱敏错误。MCP 服务由目标 Agent 自行管理，本工具不新增常驻代理。连接检查可能启动进程或发出网络请求，用户需主动点击；结果只证明本工具此次检查的状况，不能证明每个 Agent 都已连接成功。

插件操作：展示已识别项及所属生态，进入原生管理方式。仅在有可靠发现机制时显示完整列表，否则标明扫描范围。平台专属插件不自动转换成其他生态插件。

### Agent 与项目

按 Agent 查看全局配置、指定项目配置及关联资源；按项目查看配置来源、覆盖关系和冲突。只有官方语义可确定时才展示最终生效判断，否则标记“需要在 Agent 中确认”。

### 变更预览与历史

逐项展示目标、受影响文件、增删改差异、凭据处理方式、应用后需重启或重载的步骤。历史记录保留操作结果、备份和恢复入口，敏感值脱敏。

### 设置

管理资源库存放位置、已添加项目、凭据引用、导入导出和备份。账号登录、云同步、团队权限、使用量统计及自动推荐延期。

## 关键流程

### 首次盘点与接管

1. 用户启动应用，扫描已知全局位置；展示已发现内容和失败原因。
2. 用户主动添加项目，查看项目资源和全局配置关系。
3. 选择要纳入共享库的 Skills，记录来源和各目标安装关系。
4. 对同名不同内容展示差异，选择共享版本或分别保留；缺少来源时记为本地资源，不编造上游。
5. 生成变更预览，用户确认后备份并应用。

### 跨 Agent 分配

1. 选择共享资源和目标 Agent、作用域。
2. 校验目标支持、必需依赖、路径和已有冲突；不支持的操作说明具体原因。
3. 预览目标配置与文件差异，凭据脱敏。
4. 应用前重新读取受影响文件；与预览时不同则要求重新预览。
5. 应用后报告每个目标的成功、失败和待重载步骤。部分失败不显示整体成功，提供对已写入内容的恢复。

### 更新与外部修改

更新先获取上游变化，展示差异，由用户主动应用；固定版本跳过自动升级。外部修改先标记并比较，不在后台覆盖。恢复历史备份前同样比较当前文件，避免覆盖恢复之后新增的用户改动。

### 移除与删除

“从 Agent 移除”只解除目标安装关系；共享库和其他目标保留。“删除共享资源”列出仍引用它的 Agent 与项目，由用户明确处理这些关系。不能顺带删除来源 Git 仓库、本地原始目录或不属于本工具的文件。

### 导出与导入

导出共享资源、版本标识、来源和目标分配描述，默认排除凭据与凭据备份。导入先检查版本、缺失依赖、同名冲突和目标路径，预览后再写入。插件只导出有证据支持的元数据和原生管理信息，不承诺复制后即可使用。

## 配置与凭据的实现约束

- 用户原有配置中的未知字段、注释和不相关条目尽量保留，配置格式错误时停止该文件写入并给出位置。
- 共享库是已接管资源的管理基准；Agent 当前配置和运行状态仍需重新读取确认。
- 不将“复制成功”表述为“Agent 已加载”。是否支持符号链接、如何重载必须逐适配器核实。
- 跨端钥匙串供密已延期。应用不读取 Agent 的 OAuth 存储，不自动迁移密钥；MCP 预览隐藏字符串值，已有凭据仅保留在原生配置和私有备份中。
- 凭据迁移和含密配置备份需同时设计，不能只隐藏界面而把敏感值写入普通历史日志。
- 本地导入和展示不执行资源附带脚本；MCP 检查及原生安装动作由用户明确触发。

## 第一版验收标准

| 场景 | 可观察结果 |
| --- | --- |
| 盘点 | 四个 Agent 分别报告发现情况、扫描范围、资源和异常；未支持项清楚标明 |
| Skill 去重 | 同名不同内容可比较；来源和版本不明时如实显示 |
| Skill 分配 | 选定共享版本并分配到指定 Agent，其他目标不受影响 |
| 预览与并发修改 | 显示准确差异；预览后外部修改会触发重新预览 |
| 更新与固定 | 可检查上游差异、固定版本、手动更新与回退 |
| MCP 管理 | 支持的目标可添加配置并检查连接；错误可读且脱敏 |
| 插件管理 | 展示已识别插件、支持边界和原生管理入口 |
| 移除与删除 | 移除单个安装关系不删除共享资源；删除前列出引用 |
| 备份与撤销 | 可恢复工具写入的内容；存在后续修改时先处理冲突 |
| 导入导出 | 在新位置预览并恢复资源描述与分配，默认不含凭据 |
| 生命周期 | 关闭窗口后退出；按需操作，不依赖后台常驻服务 |

## 实施前评审

初步调查指出两个需要调整的假设：部分 Agent 已支持相同的 `.agents/skills` 位置，分配关系不能等同于为每个 Agent 单独复制文件；凭据引用机制也不统一，钥匙串自动供四端读取目前不能作为已验证承诺。具体来源、版本差异与未确认项见兼容性调查。

兼容性调查必须明确每个 Agent 的读、写、重载和插件管理证据。若某个目标缺少官方机制，先交付识别和引导，不用猜测格式进行写入。前端框架、具体目录、共享库复制或链接方式等工程选择，在确认约束后依据可维护性确定。

本说明是产品目标；已实现行为、实际验证与限制单独记录在 implementation.md，不能把此处验收标准当作测试通过记录。用户已确认 Q23 凭据范围调整与 Q24 进入实现。
