# 变更历史、设置与备份：完善结果

更新日期：2026-11-10。本轮已实施此前确认的四项改进。

## 当前行为

- 历史计划保存 `undo_of`，历史记录保存 `undo_of` / `undone_by`。撤销/恢复应用成功后才关联原记录；失败不提前改变原记录状态。原记录显示已撤销或已恢复并禁用重复按钮，反向记录可继续生成反向操作，实现受快照检查约束的重做。
- 应用时再次检查原记录是否已处理，阻止两个并存预览对同一原操作重复应用。反向操作链更新祖先记录的有效状态。
- 历史接口从已知原生路径识别所需项目，排除当前全局 MCP 配置和全局 Skill 目录。未添加项目在页面明确标示，按钮通过原生目录选择器重新授权，要求选回原路径；后端范围与符号链接检查保持不变。旧项目移动或路径变化不能自动替换为新路径。
- 失败恢复预览逐目标说明：已是操作前内容、仍是操作写入内容、存在后续修改/部分写入。最后一种明确提示将覆盖当前内容，保留差异预览和应用前快照复核，不静默合并。
- 备份导入默认跳过同来源资源，保留本机内容与固定状态；用户可选择覆盖同来源管理副本、版本与固定状态。预览统计新增/覆盖/跳过，并逐项列明处理。其他本机资源保留。全跳过时返回无需导入，不写入任何管理文件。
- 设置页明确：备份只包含 Skill 管理内容与分配参考，不含原生 MCP、凭据、项目列表、变更历史与私有操作备份。导入不自动分配到 Agent。
- 历史页说明它记录已应用计划，不把项目列表/固定状态等直接设置改动冒充成完整审计日志。

# 变更历史、设置与备份功能检查

日期：2026-11-10。结论：核心数据路径可用，仍有状态呈现、操作引导和导入策略说明缺口。本轮只检查并补充隔离用例，没有修改产品逻辑或真实 Agent 数据。

## 确认的问题

1. **撤销后原记录状态不更新（已复现）**：应用撤销计划会新增一条 applied 记录，原记录仍是 applied，页面继续显示“已应用 / 预览撤销”。再次预览原记录时被快照检查拒绝，提示后续变更。数据没有重复撤销，但状态与用户操作不一致。建议关联原记录和撤销记录，区分已撤销、撤销失败和可重做状态，不能仅修改显示文字。
2. **移除项目后旧记录撤销缺少恢复入口（已复现）**：项目移除不删除文件，但 authorize_change 已不允许访问该项目目标，历史页原撤销按钮仍在。重新添加同一路径可恢复权限。安全限制正确，界面应明确标示“需重新添加项目”，通过原生目录选择器授权后继续，不能绕过范围校验。
3. **导入的合并/覆盖规则说明不足（静态代码确认）**：import_library 保留其他本地管理项，同来源 ID 的现有副本、版本与 pinned 状态被备份中的记录替换，并重设为本机私有目录。它不是整机恢复，也不是清空后全量替换。已有逐文件差异预览和应用确认，但缺少新增/覆盖/不变的冲突摘要及同来源覆盖提示。应明确合并策略，再提供默认跳过冲突或逐项覆盖选择。
4. **失败操作的恢复需加强冲突说明（设计边界，非未告知行为）**：record.status 不为 applied 时，preview_undo 会把当前文件与失败前备份直接组成恢复计划，不要求当前文件等于该次操作写入后的快照。当前已有“可能包含操作后新增内容”的提示和预览，应用也会再次核对预览快照。仍应逐文件列明恢复将覆盖的后续修改及已自动回退的目标，避免将“预览恢复”误解为只修复失败部分。

## 备份范围与界面能力

设置页导出的是管理 Skill、来源、版本、固定状态与分配参考。它不导出原生 MCP、OAuth/凭据、项目列表、installations、变更历史或私有操作备份。界面已经说明主要 Skill/MCP 边界，不能把它当作整个应用或本机 Agent 的灾备文件。

导入不会按分配参考自动写入 Agent，也不自动添加旧机器项目。源路径仍保留原机器位置，需要用户核对后手动分配。

项目添加/移除与 Skill 固定状态更新直接保存设置，不进入计划历史；因此“变更历史”目前覆盖的是已应用的计划，不能视为所有设置变动的审计日志。

本机存储区目前仅显示目录文字，没有打开备份目录或逐条查看原始备份的页面入口。历史页没有原计划与撤销计划的关联详情。可作为后续完善项，不能声称已经具备。

设置页各 Agent 按钮调用固定的官方文档链接，并非启动客户端的原生设置窗口。
